# exposure-bias-recommenders

How much relevance a popularity debias costs, on Amazon Reviews 2023 (Electronics).
Implicit-feedback ALS generates candidates; a seller-size penalty re-ranks them. Exposure and
relevance are measured on separate user populations and reported per popularity and seller
bucket.

**Status:** contract and metrics are written and tested; the pipeline stages are not.
`report/INTERFACE.md` is the frozen contract — every schema, metric signature and loader
signature lives there, and a new field is added there before it is implemented.

## Layout

```
report/INTERFACE.md      frozen contract
report/DATASET_FACTS.md  dataset and library facts, cited to primary sources
src/metrics.py           ranking and exposure metrics, stdlib only
tests/test_metrics.py    52 tests, expected values hand-computed
scripts/                 pipeline stages 01-06 — not yet written
src/amazon_loader.py     not yet written
```

## Pipeline

Each stage is independently runnable; `INTERFACE.md` §6 lists what each guarantees.

```
01_prepare.py      ratings/items parquet, catalogue view, evaluation populations
02_train.py        ALS factors, candidate scores
03_evaluate.py     NDCG / hitrate / exposure for ALS, MostPop, Random
04_rerank.py       lambda sweep over the seller-size penalty
05_report.py       tables and figures from results/*.json
06_sensitivity.py  optional; 05_report.py skips its panel when the file is absent
```

## Running

```bash
python3 -m unittest discover -s tests
pip install -r requirements.txt
```

## Method notes

- ALS trains on every interaction. Evaluation populations (`>= 1` positive for exposure, `>= 2`
  for relevance) and the catalogue (`>= 3` train interactions) are views applied downstream,
  never drops at prepare time.
- A positive is `rating >= 4`. Below that is unobserved, not negative.
- Popularity buckets are cut on interaction mass, not item percentile — item counts tie heavily
  at 1–2.
- Seller size is catalogue item count.
- Both re-ranker terms are z-scored per user, so lambda is in standard deviations of score.

`data/` and `results/` are gitignored and regenerated by the pipeline.
